# Решения и допущения

## Где ТЗ не давало однозначного ответа
- **Правка задачи.** Постановщик может править название, описание и объект, пока задача
  не принята. Принятая задача заморожена.
- **Удаление задачи.** Удалить можно только задачу в статусе «Новая», то есть до начала работы:
  иначе вместе с ней пропала бы история.
- **Смена исполнителя.** Только в статусах «Новая» и «На доработке»: пока исполнитель
  работает или задача на проверке, переназначать нельзя.
- **Удаление объекта.** Объект, в котором есть задачи, удалить нельзя: база откажет,
  интерфейс покажет причину. Сначала нужно удалить или перенести задачи.
- **Что видит исполнитель в карточке объекта.** Только свои задачи этого объекта,
  чужие — нет (ТЗ: «не может прочитать чужие задачи»).
- **Кто может принять или вернуть.** Любой постановщик, не только автор задачи
  (ТЗ: постановщиков может быть несколько, и постановщик «видит всё»).
- **Исполнитель задачи.** Назначить можно только пользователя с ролью «исполнитель».
- **Комментарий.** Обязателен при возврате на доработку (пустой или из одних пробелов
  не принимается); при остальных переходах — по желанию.
- **Роли.** Хранятся в таблице профилей; менять роль через сайт нельзя — только
  администратором в базе. Пользователь без профиля не видит ничего.
- **Список исполнителей и имена в истории.** Всем вошедшим видны имена и роли
  пользователей — иначе нельзя показать, кто сменил статус.

## Технические решения
- Переходы статусов — одна функция в базе `change_task_status`; прямое изменение
  статуса запросом к таблице запрещено триггером.
- История пишется только базой; у клиентов нет прав на запись в таблицу истории.
- Хостинг — свой сервер: статика за общим веб-сервером Caddy с HTTPS (deploy/). В сборку
  попадают только публичные URL проекта и anon-ключ.

## Что не успел или сознательно не делал
- Переоткрытие принятой задачи. ТЗ прямо запрещает переходы вне таблицы, а «Принята» —
  конечный статус. Если после приёмки нашлась проблема, постановщик ставит новую задачу
  по тому же объекту. Связь «задача-продолжение» и кнопка «создать на основе» — возможное
  развитие, в ТЗ их нет.
- Управление пользователями из интерфейса (создание, смена роли) — через скрипт и консоль Supabase.
- Поиск, фильтры, пагинация, вложения, уведомления.
- Разделение «Мои задачи» по объектам и сортировки сверх базовой.
